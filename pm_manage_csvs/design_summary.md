# Design Summary — `pm_manage_csvs` MCP Server

> **Living design doc.** Mark this up freely before implementation. Anything marked TODO or unclear will be resolved during the design phase.

---

## Context

The pm Hermes agent (Telegram-based property-management assistant) currently tracks everything in local Markdown files (`PROPERTIES.md`, `TENANTS.md`, `TASKS.md`). These are brittle — no concurrent edits, no views from the property manager (Tuan Tran) outside the chat, no structured querying.

**Goal:** Build a custom Python MCP server (`pm_manage_csvs`) that exposes a clean tool surface for reading and writing structured Google Sheets that represent the same data, using the service account already created (`pm-hermes-drive@hermes-pm-505200.iam.gserviceaccount.com`).

**Five CSV types:**
1. `properties` — address list with units
2. `tenants` — per-unit tenant info
3. `vendors` — vendor directory (Chris, Sharon, etc.)
4. `maintenance` — task tracking (replaces `TASKS.md`)
5. `events` — inspections, move-ins/outs, and other dated events

**Access pattern:** Read + write, **no deletes**. Row append or full-row update only.

### `src/pm_manage_csvs/` — application code

| File | Key exports | Purpose |
|------|-------------|---------|
| `__init__.py` | `__version__` | Package marker; version string for logging |
| `__main__.py` | (entry point) | `python -m pm_manage_csvs` calls `server.mcp.run()` with stdio transport |
| `server.py` | `mcp: FastMCP`, all `@mcp.tool()` decorated functions | The MCP server. Imports `drive`, `sheets`, `schema`, `cache`. Stateless except for `cache` singletons. |
| `drive.py` | `get_drive_service()`, `list_sheets_in_folder(folder_id)`, `resolve_sheet_id(folder_id, name)` | Thin wrapper over Google API client. Builds `drive` service from `GOOGLE_APPLICATION_CREDENTIALS`. |
| `sheets.py` | `read_sheet(sheet_id, range_a1)`, `append_rows(sheet_id, rows)`, `update_row(sheet_id, row_index, values)` | Higher-level Sheets API: list-of-dicts ↔ A1 ranges. |
| `schema.py` | `SCHEMAS: dict[str, Schema]`, `validate_rows(name, rows)`, `apply_auto_fills(name, rows)` | Single source of truth for column definitions and enum/date coercion. |
| `models.py` | `Property`, `Tenant`, `Vendor`, `MaintenanceRow`, `EventRow` (pydantic BaseModel) | Typed row records. Used for input validation and serialization. Not persisted — pure runtime types. |
| `cache.py` | `TTLCache[K, V]`, `get_sheet_id(logical_name)` | In-process cache for Drive file IDs and parsed schemas. Survives only within one MCP process lifetime. |
| `errors.py` | `PMCError` (base), `ConfigError`, `SheetNotFoundError`, `ValidationError`, `APIRateLimitError` | Typed exceptions so MCP tools can return `{error: "..."}` payloads instead of crashing the subprocess. |
| `logging.py` | `get_logger(name)`, `log_event(event, **fields)` | Structured stderr logging. Format: `ts=<iso> level=INFO event=read_csv csv=properties rows=10`. Crucial for debugging because MCP stdio traffic can be opaque. |

## Code-organization conventions

- **Single responsibility per module.** No file imports from more than 3 siblings.
- **No global state.** `cache.py` is the only stateful module, and only via explicit `TTLCache` instances.
- **Tools return JSON-serializable types only** (`dict`, `list`, `str`, `int`, `float`, `bool`, `None`). Pydantic models are dumped via `.model_dump()` at the tool boundary.
- **All errors caught at tool boundary** → return `{"error": "...", "detail": "..."}`. The agent surfaces these to the user naturally.
- **Logging goes to stderr only.** Never stdout — that's reserved for MCP JSON-RPC frames.

---

## Out-of-scope (deferred for now)

- Hot-reload of `sheets.yaml` — server reads config once at startup; requires restart to pick up changes.
- Multi-folder support — single folder_id in v1.
- Custom retry/backoff policies — rely on the Google API client's built-in retry for now.
- Per-tool permissions (e.g., vendors can read but not write) — deferred to a future SOUL.md-driven layer.

## Dependencies

All deps installed via `uv add`. Runtime vs dev are split in `pyproject.toml` under `[project.dependencies]` and `[dependency-groups]`.

### Runtime dependencies

| Package | Version pin | Why it's needed | Used by |
|---------|-------------|----------------|---------|
| `mcp[cli]` | `>=1.10,<2.0` | MCP SDK — FastMCP server, `@mcp.tool()` decorators, stdio transport. `[cli]` extra gives us the `mcp` console entry for ad-hoc testing. | `server.py`, `__main__.py` |
| `google-api-python-client` | `>=2.150,<3.0` | Official Google APIs client. Wraps Drive v3 and Sheets v4 REST endpoints. | `drive.py`, `sheets.py` |
| `google-auth` | `>=2.35,<3.0` | Service-account credentials loader. Reads the JSON key from `GOOGLE_APPLICATION_CREDENTIALS`. | `drive.py` |
| `pydantic` | `>=2.8,<3.0` | Typed row models (`Property`, `Tenant`, etc.) + validation at MCP tool boundary. v2 for the cleaner `.model_dump()` API. | `models.py`, `schema.py`, `server.py` |
| `pyyaml` | `>=6.0,<7.0` | Parse `config/sheets.yaml`. | `server.py` (config load at startup) |
| `structlog` | `>=24.4,<25.0` | Structured JSON logging to stderr. Easier to grep MCP server logs than stdlib `logging` format. | `logging.py` |

### Dev / test dependencies

| Package | Version pin | Why it's needed |
|---------|-------------|-----------------|
| `pytest` | `>=8.3,<9.0` | Test framework. |
| `pytest-asyncio` | `>=0.24,<1.0` | Required because FastMCP tool handlers are `async def`. |
| `ruff` | `>=0.6,<1.0` | Single tool for linting + formatting (replaces black + isort + flake8). Runs in `make lint` / `make fmt`. |
| `mypy` | `>=1.11,<2.0` | Static type checking on `src/`. Strict mode; this codebase is small enough to keep fully typed. |
| `freezegun` | `>=1.5,<2.0` | Freeze `datetime.now()` in tests so `created_at` auto-fill assertions are deterministic. |

### Deliberately NOT pulled in

| Considered | Why skipped |
|------------|-------------|
| `cachetools` | Adding a dep for ~30 lines of TTL-dict code isn't worth it. We hand-roll `cache.py` with `time.monotonic()` + `asyncio.Lock`. |
| `python-dotenv` | The server reads `GOOGLE_APPLICATION_CREDENTIALS` from the OS env, which hermes sets via `~/.hermes/.env`. No need to load a project-local `.env`. |
| `httpx` | Already transitively pulled in by `google-auth` for token refresh. We don't call REST directly. |
| `tenacity` | Google API client has built-in retry for transient errors. Adding a second retry layer obscures failures. |
| `click` / `typer` | No CLI surface beyond `python -m pm_manage_csvs`. The MCP server doesn't expose commands. |
| `rich` | Logs go to stderr as JSON, not pretty-printed to TTY. |
| `pandas` | Overkill — we deal with ≤10k rows per Sheet and want plain dicts at the API boundary. Pulling pandas doubles install size. |
| `attrs` / `dataclasses` | Pydantic gives us both validation and serialization in one. |

### Version-pinning strategy

- **Caret ranges** (`>=X.Y,<X+1.0`) for runtime deps — allows patch + minor updates but blocks breaking majors. uv.lock pins exact transitive versions.
- **`uv.lock` committed to git** — every install is reproducible across machines.
- **Python version pinned to 3.11** in `.python-version` to match the hermes-agent venv (`/home/suncowiam/.hermes/hermes-agent/venv`).

## Schemas

### `properties`
| col | header        | type    | notes                                        |
|-----|---------------|---------|----------------------------------------------|
| A   | address       | string  | required, primary key (e.g. "2769 Oakmont St") |
| B   | city          | string  |                                              |
| C   | state         | string  | 2-letter                                     |
| D   | zip           | string  |                                              |
| E   | units         | string  | comma-separated list (e.g. "A1,A2,B1") or blank for single-unit |
| F   | notes         | string  | free text                                    |

### `tenants`
| col | header        | type    | notes                                |
|-----|---------------|---------|--------------------------------------|
| A   | property      | string  | matches properties.address           |
| B   | unit          | string  | e.g. "A1", "1412", "" if no units    |
| C   | tenant_name   | string  | required; comma-separated for co-tenants (e.g. "Dominique Davis, Bob") |
| D   | phone         | string  | comma-separated for multiple phones, in same order as tenant_name |
| E   | email         | string  | comma-separated for multiple emails  |
| F   | lease_start   | date    | YYYY-MM-DD                           |
| G   | lease_end     | date    | YYYY-MM-DD or blank                  |
| H   | status        | enum    | `active` / `notice` / `moved_out`    |
| I   | notes         | string  |                                      |

Primary key: `(property, unit)`. Co-tenants on the same lease share a row — `tenant_name`, `phone`, and `email` are comma-separated lists aligned positionally.

### `vendors`
| col | header        | type    | notes                                |
|-----|---------------|---------|--------------------------------------|
| A   | name          | string  | required, primary key                |
| B   | role          | string  | e.g. "handyman", "planner"           |
| C   | phone         | string  |                                      |
| D   | email         | string  |                                      |
| E   | telegram_id   | string  | for Telegram contact                 |
| F   | active        | bool    | true/false                           |
| G   | notes         | string  |                                      |

### `maintenance` (replaces `TASKS.md`)
| col | header        | type    | notes                                       |
|-----|---------------|---------|---------------------------------------------|
| A   | property      | string  | FK → properties.address                     |
| B   | unit          | string  | optional (single-unit properties have empty) |
| C   | owner         | enum    | `tuan` / `chris` / `sharon` / `vendor` (person names; Tuan Tran is the manager)   |
| D   | start_date    | date    | YYYY-MM-DD — sufficient on its own; no separate `created_at` |
| E   | end_date      | date    | YYYY-MM-DD or blank                         |
| F   | issue         | string  | required                                    |
| G   | status        | enum    | `open` / `in_progress` / `done` / `cancelled` |
| H   | notes         | string  |                                             |
| I   | completed_at  | date    | auto-filled when status → done              |

Primary key: row index (no natural key — tasks are append-only).

### `events`
| col | header        | type    | notes                                          |
|-----|---------------|---------|------------------------------------------------|
| A   | date          | date    | YYYY-MM-DD, required                           |
| B   | property      | string  | FK → properties.address                        |
| C   | unit          | string  | optional                                       |
| D   | event_type    | enum    | `shra_inspection` / `move_in` / `move_out` / `walk_through` / `notice_served` / `eviction` / `other` |
| E   | description   | string  | required                                       |
| F   | status        | enum    | `scheduled` / `completed` / `cancelled` / `pending_result` |
| G   | notes         | string  |                                                |

Primary key: row index (append-only log).

## MCP Tool Surface

All tools prefixed with `mcp_pm_manage_csvs_*` by Hermes. Names below are unprefixed.

### Discovery / read

| Tool | Description |
|------|-------------|
| `list_csvs` | Return the 5 logical names: `["properties", "tenants", "vendors", "maintenance", "events"]` |
| `get_schema(csv_name)` | Return headers + types + primary key info for a CSV |
| `read_csv(csv_name, max_rows=1000)` | Return all rows as list of dicts |
| `read_csv_rows(csv_name, filters)` | Return rows matching filters, e.g. `filters={"property": "2769 Oakmont St", "status": "active"}` |
| `count_csv_rows(csv_name, filters?)` | Count matching rows |

### Write

| Tool | Description |
|------|-------------|
| `append_rows(csv_name, rows)` | Append one or more new rows. Validates headers. Auto-fills `created_at` on `maintenance`. Returns indices of appended rows. |
| `update_row(csv_name, row_index, values)` | Overwrite values in an existing row. Refuses to update `created_at` / primary key. Auto-fills `completed_at` when status→`done` on maintenance. |

### What is **NOT** exposed (intentional)

- `delete_row` — to "remove" a row, set its status to `cancelled` / `moved_out`.
- Schema mutation — schemas are fixed in code.
- File management — creating new Sheets / renaming is not exposed.

## Implementation Steps

### 1. Scaffold project
```bash
mkdir -p src/pm_manage_csvs config tests tests/fixtures
uv init --no-readme --no-pin-python
uv add "mcp[cli]" google-api-python-client google-auth pydantic pyyaml
```

### 2. Create `config/sheets.yaml` with folder_id placeholder

### 3. Implement `drive.py`
- `get_drive_service()` — builds service from `GOOGLE_APPLICATION_CREDENTIALS` env var.
- `list_sheets_in_folder(folder_id)` — Drive API `files.list` with `q: "'<folder_id>' in parents and mimeType='application/vnd.google-apps.spreadsheet'"`.
- `resolve_sheet_id(folder_id, logical_name)` — cache lookup + fallback to listing.

### 4. Implement `schema.py` — column definitions per csv type, validate_rows helper

### 5. Implement `sheets.py`
- `read_sheet(sheet_id, range_a1)` → list of dicts.
- `append_rows(sheet_id, rows)` → Sheets API `values.append` with `valueInputOption=USER_ENTERED`.
- `update_row(sheet_id, row_index, values)` → Sheets API `values.update`.

### 6. Implement `server.py` using FastMCP
```python
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("pm_manage_csvs")

@mcp.tool()
def list_csvs() -> list[str]: ...

@mcp.tool()
def read_csv(csv_name: str, max_rows: int = 1000) -> list[dict]: ...

# ... etc
```

### 7. Implement `__main__.py`
```python
from .server import mcp
if __name__ == "__main__":
    mcp.run()  # stdio transport
```

### 8. Wire into hermes `profiles/pm/config.yaml` — alongside the existing `gdrive` MCP server:
```yaml

    command: "/home/suncowiam/.hermes/mcp_servers/pm_manage_csvs/.venv/bin/python"

    timeout: 120
```

### 9. Update `profiles/pm/workspace/DRIVE_NOTES.md` — add section pointing to `pm_manage_csvs_*` tools as the preferred interface for read+write on the 5 Sheets.
